# 项目加载协议

## 入口扫描

1. 定位含 `AGENTS.md`、`00_项目总控/` 和 `01_故事圣经/` 的项目根。
2. 先读根规则，再读 `00_项目总控/设定索引.md`、`正史优先级与文件边界.md` 和将要修改目录的 README。
3. 检查目标文件是否存在，不按旧提示词或模型记忆猜路径。
4. 从索引按任务读取，不递归吞入整个仓库。

## 最小读取集合

| 任务 | 优先读取 | 仅在需要时补充 |
|---|---|---|
| 正式设定 | 总控规则＋目标正式文件 | 直接相关的其他正史文件 |
| 总体故事 | 作品定义＋总体故事线＋九卷总纲 | 主时间轴、相关人物关系 |
| 故事池 | 总体故事线＋相关人物 | 时间轴、地点池、相关机设 |
| 分卷/剧情单元 | 总体故事线＋九卷总纲＋相关人物 | 主时间轴、故事池、专项资料 |
| 章纲 | 当前卷/单元＋相关人物 | 前后章纲、时间轴、车辆、研究卡 |
| 连续正文 | 当前单元纲要中本章及前后衔接部分＋最新章节事实摘要或章末状态＋上一章末尾相关段落＋本章出场人物 | 仅当本章直接承接尚未结束的行动、对话、情绪或伏笔时扩读上一章相关场景；只有整体连续不可分割时才读上一章全文。发生连续性风险时再读时间轴、状态表和专项设定 |
| 对白专项或关系转折 | 当前场景＋在场人物＋直接相关人物关系 | 人物对话总则、最近正文；仅在写反或需要校准时补读 |
| 车辆情节 | 车辆体系上位摘要＋对应专项机设 | 车辆状态、时间轴、相关人物 |
| 关系情节 | 各方人物卡＋直接相关人物关系 | 当前状态、最近正文、人物弧线 |
| 现实研究 | 待写情节＋已有研究卡 | 官方或一手外部来源 |
| 美术一致性 | 人物/车辆正式视觉说明＋资产 README | 必要图片、正文场景 |

连续正文默认不加载上一章全文或更早全部正文。若尚无章节事实摘要，先读取上一章末尾并临时提炼当前入口状态；第一章没有前文时，直接以已确认单元纲要、相关人物和正式文风为主要依据。

独立章节卡不是连续正文的必备输入。正式单元纲要已经包含章节中心、主要事件、场景顺序、章末状态和必要事实时，直接使用单元纲要；只有用户明确要求或章节复杂到纲要不足以控制行动、空间、时间或多线并行时，才按需制作章节卡。

已经在当前会话中读取且没有发生更新的文件，不为完成流程重复读取。局部修改、人物声音测试和独立试写不自动升级为完整章节加载。

## 缺失处理

- 连续正式正文原则上应有章纲或已确认单元纲要；用户明确要求人物声音测试、独立场景试写或局部改写时可以直接起草，但不得自动视为正式正史或写回正文目录。
- 缺少状态表但尚无正文变化时，不创建空台账。
- 缺少关键正史或路径冲突时，报告影响，不用旧版资料和模型记忆补齐。
- 普通场景细节不足时，可以在不锁定新正史的范围内自然处理。
